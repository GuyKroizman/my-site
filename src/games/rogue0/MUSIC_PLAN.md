# Rogue0 — Dynamic music (Peter-and-the-Wolf style)

Goal: add reactive, **original** orchestral music to Rogue0. Real instrument
timbres come from SoundFont-derived sample files played by a browser loader;
the notes, rhythms and layers are generated by our own code. Instruments act as
distance-based clues about nearby monsters, the way Prokofiev's instruments
identify the characters — but with a different tune.

## Agreed decisions

- **Sound source:** ship SoundFont-derived, pre-rendered **per-instrument**
  files (the `.js`-wrapped ogg/mp3 format used by `soundfont-player`) and load
  them with `soundfont-player` (MIT). No oscillator-synthesised instruments and
  no raw multi-hundred-MB SF2 at runtime. Note: `soundfont-player` does *not*
  parse `.sf2` in the browser — it loads one small file per instrument.
- **Composition:** original motifs + constrained code variation. Code
  transposes, changes rhythm and layers motifs within fixed keys/chord
  progressions; it does not invent a fresh random melody each run.
- **Hint rule:** distance-based, audible through walls and closed doors.
  Mimics stay silent until triggered; sleeping monsters play faintly.
  Non-visible cues are quieter, so a monster behind a door is hinted at but
  less insistent. (Per-cue low-pass filtering was considered but not built;
  distance is conveyed by level only.)
- **Cast:** strings (calm bed), plus a distinct instrument and motif for every
  monster — clarinet (Goblin), pizzicato strings (Skeleton), oboe (Ghoul),
  trombone (Brute), bassoon (Cultist), flute (Wraith), piccolo (Quloptsh),
  tuba (Mimic), marimba (Deadly Frog), tremolo strings (Swarm of Flies),
  trumpet (Fire Elemental), glockenspiel (Ice Elemental), xylophone (Lightning
  Elemental), French horn + timpani (boss). Only cued monsters affect tension.
- **Controls:** separate music toggle and volume slider in the HUD, persisted
  in localStorage. The existing SFX mute button keeps working independently.

## Current state (source-audited)

- `audio.ts` is a single `AudioContext` singleton with procedural `sfx.*`
  one-shots. `tone()`/`noise()` check `muted` at call time, which is fine for
  one-shots but wrong for continuous music — music needs a master gain node.
- `unlockAudio()` is called from `startGame`/`continueGame` in `Rogue0.tsx`
  (lines 214–234). The HUD's existing sound button is at lines 458–464.
- `Rogue0.tsx` destroys the Phaser game on unmount, but the audio singleton
  survives; continuous music therefore needs an explicit `stopMusic()`.
- `scene0.update()` starts at line 723; FOV is refreshed at line 776 via
  `refreshFovIfNeeded()`. That is the natural place to re-evaluate the music
  state, throttled.
- Signals available: `context.entities`, `context.player`,
  `context.visibleTiles`, `bodyDistance()` from `actorBodies.ts`, and each
  monster's `sleeping` getter and `awareOfPlayer` flag.
- Monsters currently have only a `name` string; there is no stable music
  identifier. A `musicCue` identifier is needed for clean mapping.
- Node test fixtures import these modules. Audio/sample loading must stay
  browser-lazy: no fetch, `window`, or `AudioContext` at import time.

## Architecture

Three pieces, kept separate so the musical decisions are testable without a
browser.

### 1. `musicState.ts` — pure state selector

`selectMusicState(context): MusicState` returns:

```ts
type MusicCue = 'goblin' | 'boss';
type MusicState = {
  intensity: 'calm' | 'uneasy' | 'combat' | 'boss';
  cues: Array<{ cue: MusicCue; level: number; visible: boolean }>;
};
```

Rules:

- Ignore items, decoys and dead entities. Use `bodyDistance(player, enemy)`
  for tile distance (body-aware, matching AI/combat).
- Audible radius ~8 tiles, walls and closed doors do not block sound.
  Level rises as distance falls (faint at 8, medium at 5, strong at 2).
- A cue is `visible: true` when its tile is in `context.visibleTiles`;
  otherwise it is quieter and low-pass filtered by the engine.
- Sleeping monsters contribute at 25% level. Mimics contribute **only once
  awake/triggered** — a dormant mimic disguised as a chest must not betray
  itself with its own motif.
- Any living boss on the floor forces `intensity: 'boss'` and its cue at full
  level regardless of distance; all other cues are suppressed.
- Otherwise: `combat` when an awake monster is within ~3 tiles or
  `awareOfPlayer`; `uneasy` when any cue is audible; `calm` when none are.

The selector is a plain function of `context` — no audio, no Phaser objects —
so it can be unit-tested with the existing fixture style.

### 2. `musicComposer.ts` — original motifs + constrained variation

- Fixed key per intensity (e.g. D minor for calm/combat, a lowered/tense
  colour for boss) with a short chord progression (i–VI–III–VII).
- Original motifs as note data, e.g. a four-bar strings phrase for the hero,
  a short staccato clarinet figure for the Goblin, a low horn statement with
  timpani downbeats for the boss. These are **our** melodies, not Prokofiev's.
- Transformations applied in code: transpose within the scale, rhythmic
  augmentation/diminution as intensity rises, inversion, and simple harmony
  (thirds/sixths) in the strings. Variations cycle in a fixed order driven by
  game state, not RNG, so the music stays coherent and recognisable.
- Output is a list of scheduled note events `{ instrument, pitch, time,
  duration, gain }` for a short lookahead window.

### 3. `audio.ts` (extended) — music engine

- Load the instrument files lazily, after `unlockAudio()`, from a local
  directory `public/rogue0/audio/` using `soundfont-player`. Never fetch from a
  remote CDN. Use a dynamic `import()` so the loader and samples are a separate
  chunk: the game starts immediately and music fades in when the files are
  ready, with no blocking load screen. Fetch or loader failures call
  `context.onMusicError(message)`; React shows a visible error and exits the
  run. There is deliberately **no silent fallback** — the game must not
  continue with music missing.
- Files are SoundFont-derived (FluidR3_GM → MIDI.js soundfonts, CC BY 3.0);
  attribution goes in `public/rogue0/audio/LICENSE`. Avoid MusyngKite-derived
  files, which are CC BY-SA 3.0. Each instrument file is ~2–3 MB, so the
  five-file slice totals roughly 12 MB.
- Route all instruments through a **music master gain** (volume) and a light
  `ConvolverNode` reverb with a generated impulse response — "room" without
  synthesising instruments.
- A lookahead scheduler (~25 ms tick, ~100 ms ahead) pulls note events from
  the composer and plays them at explicit AudioContext times.
- API: `startMusic()`, `stopMusic()`, `setMusicMuted()`, `setMusicVolume()`,
  `updateMusic(state)`. Mute changes the master gain immediately; it does not
  wait for the next note.
- Crossfade between intensity states (~0.5–1 s) instead of hard-cutting;
  cues fade in/out as monsters enter or leave the radius.
- If the loader does not expose an output/destination option, wrap or patch
  its note output so it reaches the master gain rather than `destination`.

## Wiring

- **Monsters:** add optional `musicCue?: MusicCue` to `MonsterConfig`, set on
  the Goblin and Boss classes, with a name-based fallback for older saves.
  The field is optional so saved floors restore unchanged.
- **`scene0.ts`:** after `refreshFovIfNeeded()` in `update()`, evaluate
  `selectMusicState(this.context)` at most every ~200 ms and call
  `updateMusic()` only when the result changes. Keep this outside the
  modal early-return so music continues while a modal is open.
- **`Rogue0.tsx`:** read/write `rogue0_musicMuted` and `rogue0_musicVolume`
  alongside the existing mute state; show a "Music: ON/OFF" button and a
  small volume slider next to the existing sound button; call `startMusic()`
  after `unlockAudio()`, `stopMusic()` in the unmount cleanup, and on
  `context.onEnd`. Set `context.onMusicError` to display the error on the
  start screen and tear down the run (destroy Phaser, clear `heroClass`).

## Risks and contingencies

- **Attribution** is the gating risk: the FluidR3_GM-derived MIDI.js files are
  CC BY 3.0, so the licence notice must ship with them. Do not use
  MusyngKite-derived files (CC BY-SA 3.0) without agreeing the share-alike
  implications.
- **Asset size:** 16 per-instrument files (~38 MB in `dist/`), not a full SF2.
  Only the five core files load at run start; the rest are fetched on first
  use, so a slow connection does not block the first frame.
- **Loader API:** note scheduling time and output routing must be verified
  against the actual package version; plan for a thin adapter.
- **Autoplay/teardown:** the audio singleton outlives Phaser, so
  `stopMusic()` must be called on unmount and on run end, or a second run
  starts with two soundtracks.
- **Hint fairness:** distance-based sound is a deliberate design choice that
  reveals monsters through walls. Mimic and sleeping exceptions protect the
  two mechanics that would otherwise be spoiled; revisit if playtesting
  shows stealth is too easy.
- **Muffled cues (deliberately omitted):** unseen monsters are quieter but not
  low-pass filtered. The shared players have no per-note destination, so
  filtering only those notes would need a second full sample set. Distance is
  conveyed by level only.
